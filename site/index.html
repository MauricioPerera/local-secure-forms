EL PROBLEMA

La terminal no tiene que ser una barrera.

Los agentes son buenos coordinando tareas, pero pedir una contraseña por chat o explicar cinco comandos para configurar una cuenta crea riesgos y errores innecesarios. LSFA reduce la interacción a lo único que importa ahora.

01

Solo lo necesario

El formulario se genera para la operación actual, no para una aplicación entera.

02

El usuario decide

Aceptar, rechazar y cancelar son acciones distintas. Las operaciones sensibles siempre requieren confirmación.

03

Resultado, no secreto

El agente recibe estado verificable. La contraseña permanece en el almacén seguro del sistema.

EL FLUJO

Una frontera clara entre intención y secreto.

01El agente solicita conectar un correo.
02La CLI abre el formulario local adecuado.
03El usuario completa y confirma.
04La CLI valida IMAP/SMTP y guarda el secreto.
05El agente recibe solo el resultado.
RESPUESTA SEGURA
{
  "status": "accepted",
  "imap_verified": true,
  "smtp_verified": true,
  "credential_stored": true
}

La contraseña nunca aparece en la respuesta, argumentos, logs ni historial de shell.
